# Phylis Beta Acceptance Script

This is the real-world validation protocol for the next phase, Phyllis beta onboarding. Do not run this against Phyllis until explicitly authorized - her invitation has not been created as part of this milestone.

## What this measures

For each of the twenty-one workflow rows in docs/PHYLIS_ACCEPTANCE_MATRIX.md, this script pairs a baseline (her current Wave/Excel/MyTAXPrepOffice workflow) against the same task performed in Folio, and records the fields below for each. Nothing in docs/PHYLIS_ACCEPTANCE_MATRIX.md or docs/competitive-intelligence/FOLIO_REPLACEMENT_SCORECARD.md is to be reported as an achieved result until this script has actually been run with her.

## Fields recorded per workflow

- Baseline workflow time: minutes to complete the task in her current stack, timed directly.
- Folio workflow time: minutes to complete the equivalent task in Folio, timed directly.
- Steps: count of discrete user actions (clicks, uploads, data entry fields) in each version.
- App switches: count of times she moved to a different application (or browser tab for a different tool) to complete the task.
- Manual corrections: count of times she had to fix an incorrect extraction, categorization, or suggestion.
- Extraction errors: count of receipt or document extraction results that were wrong and needed correction.
- Classification corrections: count of business/personal or category assignments she changed after the system's suggestion.
- P&L differences: any dollar amount on a Folio-generated P&L that did not match her independently verified figure, and the resolution.
- Unresolved evidence: count of receipts, statements, or documents that could not be matched or classified and remain open at the end of the session.
- Client chasing eliminated: count of client follow-ups that Folio's automated request flow handled without her sending a manual email.
- Hours saved: computed weekly from the timed comparisons above, extrapolated from her actual weekly volume, not assumed from the 10-hour target.

## Session structure

1. Baseline session: observe and time her performing a representative set of the twenty-one workflows in her current stack, for one real or realistic client file.
2. Folio session: same workflows, same client data, in Folio.
3. Debrief: ask her directly which steps felt faster, which felt slower, and what she would still leave Folio to do elsewhere.

## Reporting rule

Report the ten-plus-hours-per-week target and the 90-95 percent one-workspace target only as measured outcomes from this script, each with the underlying per-workflow numbers attached. A partial result (for example, six workflows measured, fifteen not yet covered) is reported as partial, not extrapolated into a full claim.

## Prerequisite

Do not run this script until Phyllis's invitation has been created and she has completed the owner-analogous onboarding (redeeming an invitation, in her case a beta invitation rather than an owner bootstrap invitation) and had time to use the product on at least one real engagement, so the comparison reflects real use rather than a first-exposure demo.
